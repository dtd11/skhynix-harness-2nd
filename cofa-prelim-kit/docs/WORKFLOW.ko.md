# 작업 흐름

## 문제를 받았을 때

1. 현재 작업 단계와 실제 남은 시간을 확인합니다. 설치는 준비일 뿐 문제 풀이를 대체하지 않습니다.
2. 문제/README/제출 파일/데이터/실행 환경부터 읽습니다. 과제의 기존 구조를 유지합니다.
3. 필수 요구사항을 짧게 분해합니다. 예: 파일 읽기, 정확한 집계, 결과 표시, 저장, 오류 처리. 실제문제에 없는 기능은 추가하지 않습니다.
4. 허용된 제공 에이전트로 해결할 업무 모호함과 구현자가 합리적으로 결정할 선택을 구분합니다. 중요한 가정/단위/해석을 기록합니다.
5. 가장 작은 사용 흐름을 끝까지 연결합니다. 최소 구현이 완성되기 전 장식/새 프레임워크/대규모 재설계를 시작하지 않습니다.

예시 명령은 프로젝트 루트 기준입니다.

```bash
python .cofa-kit/kit.py require --id R1 --text "실제 필수 요구사항"
python .cofa-kit/kit.py note --kind decision --text "선택한 방법과 실제 근거"
python .cofa-kit/kit.py require --id R1 --status implemented
```

## 오류가 날 때

`cofa-debug`를 읽습니다. 원래 증상 재현, 호출부/데이터 경계 확인, 하나의 원인 가설, 작은 수정, 같은 재현 명령 재실행 순서로 진행합니다. 실패 기록/로그를 보존합니다. 관련 없는 테스트를 지우거나 잘못된 기대값을 바꿔 통과시키지 않습니다.

단순화는 `cofa-simplify`: 정상 동작 기준이 있을 때 변경 범위를 좁혀 적용합니다. 기존 테스트가 실패하거나 마감이 임박하면 대규모 정리를 멈춥니다. 리뷰는 `cofa-review`: 실제 누락/오류를 우선하며 스타일 취향으로 범위를 늘리지 않습니다.

원본Matt/Superpowers의 전체 개발 방법론을 자동 적용하지 않습니다. 모든변경에 긴 설계문서/모든파일TDD/여러 에이전트/외부이슈 작성/사용자 반복 승인을 강제하지 않습니다. 실제 동작을 검증하는 작은 테스트는 중요한 계산·분기·파서·수정된 버그를 중심으로 둡니다.

## 검증과 제출

`cofa-verify`를 읽습니다. `check`는 명령과 전체 로그/종료코드/소스 지문을 기록합니다. 명령 전후 소스가 달라졌으면 안정된 검증으로 인정하지 않습니다. 코드가 바뀌면 과거 증거를 보수적으로 오래된 것으로 처리합니다. 지문은 검사 결과의 최신성만 확인하며 검사 대상이 요구사항에 적합한지는 판단하지 않습니다. 외부심볼링크의 내용까지 신선함을 보장하지 않으므로 과제 구현 파일은 프로젝트 안에 둡니다.

```bash
python .cofa-kit/kit.py check --name unit --timeout 120 -- npm test -- --run
python .cofa-kit/kit.py require --id R1 --status verified --evidence E1
python .cofa-kit/kit.py status
```

웹이면 참가자가 플랫폼 미리보기에서 실제로 조작합니다. 빌드 성공만으로 화면 동작을 확인했다고 말하지 않습니다. 참가자 관찰과 기계 실행을 구분합니다. 브라우저 자동화, 스크린샷 자동화, 외부 브라우저 직접 접속은 키트 기능에 포함하지 않습니다.

```bash
python .cofa-kit/kit.py manual --name manual-ui --result pass --note "참가자가 직접 확인한 주요 동작/입력/저장"
python .cofa-kit/kit.py handoff --required-file ACTUAL_REQUIRED_FILE
```

`handoff`는 필수 요구사항의 최신 통과 증거, 최근 실패 검사, 지정 필수 파일, 웹의 참가자UI확인을 검사합니다. 실제파일은 있어도 에디터가 저장 충돌/실패 상태일 수 있으니 화면에서 확인합니다. 로컬 체크리스트의 미해결 표시가 실제 플랫폼 제출을 막는 것은 아닙니다. 한계가 남으면 정확하게 기록하고 제한시간 안에 제출합니다.

미리보기 단계는 `stage --to submission-preview`, 수정하러 되돌아왔으면 `stage --to work`로 기록할 수 있습니다. 확정 뒤에는 되돌리지 않습니다. 실제 확정 후 참가자가 직접 `stage --to locked`를 기록하면 이 도구의 코드 실행·라이브러리 조회·기록 수정 명령이 중단됩니다. 이는 보조장치이며 다른 도구를 감시/통제하지 않습니다. 서술형에서는 AI로 답변하거나 검토하지 않습니다.

외부 자료 취득은 Git Clone만 사용합니다. 저장소를 가져온 뒤 `install`은 파일을 로컬에 배치하는 단계이며 인터넷 다운로드가 아닙니다. `libraries`는 기존 환경 조회만 합니다. pip/npm 설치·npx/dlx·curl/wget·소스 빌드의 추가 다운로드를 자동 실행하지 않습니다. 제공 도구가 없으면 표준 라이브러리나 기존 프로젝트 기능으로 해결 범위를 정합니다.

## 기록과 공개 저장소

공개도구함과 실제 과제작업을 분리합니다. `.cofa/`에는 문제 요구사항·결정·검사출력 등이 들어가며 `.gitignore`로 제외됩니다. `.cofa-kit`는 설치된 도구사본입니다. Git Push는 수행하지 않습니다. 로컬기록은 제출 규정/플랫폼이 요구하는 범위 안에서 사용하며 공개저장소로 복사하지 않습니다. 필요한 제출문서명은 과제기준으로 정하고 내용은 기록을 근거로 작성합니다.
